# Quarantine — 2026-08-11 (evening): before the ocean excess-¹⁴C constraint

These files are the **2026-08-11 mode**, produced against a posterior that did
**not** contain the ocean excess-¹⁴C inventory term. They are not wrong in the
way the `20260811_ar1_pathology_and_solver_wall` files are wrong — the model and
the integrator are the current ones, and the 17 parameter names match — which is
precisely why they are dangerous at a canonical path: everything about them
*looks* current.

## What changed underneath them

`ccx_loglik()` gained `excess_c14_ocean`, scoring the model's ocean excess ¹⁴C
inventory at 1975 and 1995 against Naegler & Levin (2006). See `R/likelihood.R`
design note 5 and commit `4e726b5`.

## What is and is not still usable

| | |
|---|---|
| `par_mode` as a **starting point** | fine — same 17 parameters, same meaning |
| `logpost` = **−2359.3** | **DO NOT QUOTE.** It is a different function's value. The same parameter vector scores **−2378.6** under the current posterior. |
| `hessian` / `cov` / `sd_unc` / `eigen` | **superseded.** The curvature is of the old posterior; a proposal scaled to it would be mis-scaled in the directions the new term constrains (`bomb_total`, `k_w`, `kz`). |
| `trace` | historical record only |

## The number that made this necessary

At this mode's `bomb_total` = 151.2 kmol the new term scores **−19.33**; at the
citable 102 kmol it scores **−7.31**. So the constraint moves ~12 log-units
against the mode below — real, but far short of the 116 log-units it costs to
pin `bomb_total` at 102. The mode will shift; it will not jump to 102.

**Canonical replacement:** `calibration/output/mode_fit.rds`, regenerated by
`Rscript calibration/run_modefind.R` against the posterior that includes the
term.
