# Quarantine 2026-11-11: card 3 scan, IntCal counted as ocean Δ¹⁴C

**Bug.** `calibration/diag_card3_kw_diseq_scan.R` split the 26 likelihood rows into families with
`d14c_atm = "^d14c_(NH|SH)$"` and `d14c_ocean = "^(d14c_(?!NH$|SH$)|excess_c14)"`. The second pattern caught
`d14c_intcal`, the tree-ring record, which is atmospheric Δ¹⁴C. `calibration/diag_price_profile_read.R` (`FAM`)
counts it as atmospheric. Only the two Δ¹⁴C family columns are affected; their sum, `dlik`, gate D, the
factor-at-bottles table and the gates are unchanged.

**Files here** (moved with `git mv`):
- `card3_kw_diseq_scan_20261111_hilda31fl.log` / `.rds`: the scan from 9551d7db with the `--profile` section
  (k_w = 1446 profile, start A). The version committed at 3b80ad57 / 6bade1d2 is the same scan without that section.

**Size of the error.** At k_w ×0.85 the atmospheric Δ¹⁴C cost was printed as 391.20 (correct 384.81) and ocean
Δ¹⁴C as +2.86 (correct −3.53). At the re-fitted profile point atmospheric Δ¹⁴C was +5.87 (correct +7.32) and
ocean Δ¹⁴C +1.71 (correct +0.26). The decision sheet `notes/decision_sheet_2026-11-11_group_b.md` quoted the
×0.85 value ("atmospheric Δ¹⁴C 391"); corrected in the same commit series.

**Canonical replacement:** `outputs/diagnostics/card3_kw_diseq_scan_20261111_hilda31fl.{log,rds}`, regenerated by
the fixed driver.
